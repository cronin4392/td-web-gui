# td-web-gui

Development workspace for **[`td-core`](packages/td-core)** — a Solid.js library
for building web UIs that control [TouchDesigner](https://derivative.ca/), with
bidirectional parameters over WebSocket and real-time video over WebRTC.

**→ [Package README and documentation](packages/td-core#readme)**

If you're here to _use_ the library, everything you need is in that package.
This file covers working on it.

## Layout

One library and two consumers of it. The consumers depend on `td-core`; nothing
depends on them, and they never depend on each other.

|                                        |                                                                                                                                                                                                                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`packages/td-core`](packages/td-core) | The library — the deliverable, and the only thing published. Ships the TouchDesigner-side Python in [`touchdesigner/`](packages/td-core/touchdesigner) and its docs in [`docs/`](packages/td-core/docs).                                                            |
| [`apps/example`](apps/example)         | Reference app: exercises every control against two TD instances at once. Distributed alongside the package, so it doubles as documentation. Ships its `.toe` files in [`td/`](apps/example/td).                                                                     |
| [`apps/vj-gui`](apps/vj-gui)           | The author's real VJ rig — eight scene layers, SQLite scene/effect catalogs, a phrase wordbank, and its own Vite dev-server API. Not published, but maintained and tested. Its domain vocabulary is [`UBIQUITOUS_LANGUAGE.md`](apps/vj-gui/UBIQUITOUS_LANGUAGE.md). |

Supporting directories:

|                                     |                                                                                                                                                             |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`prds/`](prds)                     | Original planning documents. Historical, superseded by the package docs, slated for removal.                                                                |
| [`TODO.md`](TODO.md)                | Loose items not yet promoted into `prds/`.                                                                                                                  |
| `td/`                               | Untracked local tooling only — the Python venv the Envoy MCP bridge runs on (see `.mcp.json`) and TouchDesigner's log output. No project source lives here. |
| `AGENTS.md`, `ENVOY.md`, `.claude/` | Generated by Embody/Envoy for AI tooling. Not hand-edited; `.claude/` is gitignored.                                                                        |

`apps/vj-gui` is the one place where the two halves of the repo can blur. Keep
its vocabulary (Scene, Effect, Layer, Loader, Wordbank) out of `td-core` — the
library knows only instances, params, calls, and streams.

## Prerequisites

- **Node.js** ≥ 24
- **pnpm** (`npm install -g pnpm`)
- **TouchDesigner** 2025.33070 to run anything end-to-end
- **[Ruff](https://docs.astral.sh/ruff/)** (`pip install ruff`) to format the
  TouchDesigner-side Python (`pnpm format` runs it alongside Prettier, and the
  pre-commit hook calls `pnpm format` automatically)

## Commands

```sh
pnpm install                      # install all workspace dependencies

pnpm --filter td-core build       # build the library -> dist/ (JSX-preserving + .d.ts)
pnpm --filter td-core test        # run the test suite once
pnpm --filter td-core test:watch  # watch mode
pnpm --filter td-core typecheck   # type-check without emitting

pnpm --filter example dev         # start the example app (Vite)
pnpm --filter example build       # production-build the example app

pnpm --filter vj-gui dev          # start the VJ app (Vite + its dev-server API)
pnpm --filter vj-gui test         # run its suite
pnpm --filter vj-gui db:scenes    # rebuild the scene catalog from VJ_SCENES_ROOT
pnpm --filter vj-gui db:effects   # rebuild the effect catalog from VJ_EFFECTS_ROOT

pnpm db:export                    # write the catalogs out to data/snapshots/*.sql (tracked)
pnpm db:restore                   # rebuild the .db files from those snapshots
```

The `.db` files are untracked; `apps/vj-gui/data/snapshots/*.sql` is the tracked
copy. `dev` restores any that are missing, and the restored rows resolve against
your own `VJ_SCENES_ROOT` / `VJ_EFFECTS_ROOT` — run `db:scenes` / `db:effects`
when the content on disk has changed, not to make a fresh clone work.

Workspace-wide: `pnpm build`, `pnpm test`, `pnpm typecheck`, `pnpm format`.

> Both apps import `td-core` from its built `dist/`, so run
> `pnpm --filter td-core build` before either `dev`.

`vj-gui` additionally needs a `.env` pointing at your TouchDesigner content
folders — copy [`apps/vj-gui/.env.example`](apps/vj-gui/.env.example).

## Running end-to-end

1. `pnpm --filter td-core build`
2. Open **both** reference projects in TouchDesigner —
   [`apps/example/td/Example1/Example.toe`](apps/example/td/Example1) and
   [`apps/example/td/Example2/Example2.toe`](apps/example/td/Example2)
3. `pnpm --filter example dev`

The example app drives two instances at once, one per column. Each `.toe` has its
own registry beside it — `apps/example/td/Example1/config.py` and
`apps/example/td/Example2/config.py` — and the two are deliberately different
shapes, which is what the multi-instance example is demonstrating. Both expect a
`/project1/params` Base COMP with one custom parameter per entry, plus a
four-tile video wall under `/project1/videowall`. Each file's docstring lists
exactly what.

Instance 1 alone is enough to exercise every control; opening only it leaves the
right-hand column showing "reconnecting…", which is itself the demonstration that
the two connections are independent.

The TouchDesigner callbacks the reference project loads live in the package now
(`packages/td-core/touchdesigner/`), so the `.toe` consumes them the same way a
user's project would. `WebGuiServer`'s **TD Core Dir** parameter points at that
folder on disk — it's a per-machine absolute path (not derived from the `.toe`'s
location, since a project isn't guaranteed to sit anywhere near the package), so
set it once after cloning.

## Testing

`td-core` is tested against an in-memory TouchDesigner — a stub WebSocket server
and a faked `RTCPeerConnection` — so the full wire contract runs in CI without a
live `.toe`. The reference project is the manual check for what can't be faked:
real WebRTC media, and reconnect on a `.toe` reload.

`vj-gui` tests its own halves the same way: its dev-server API plugins against a
temp SQLite file, its stores and pickers against fakes. It never re-tests the
library.

The TouchDesigner-side Python currently has **no automated coverage** on either
side; see [TODO.md](TODO.md).
