My codebase is read by other engineers, not just by me. Clarity matters more than brevity when something is genuinely complex or when the decision isn’t obvious from the code itself. If a comment states what the code already clearly shows, cut it. If it explains a tradeoff or a non-obvious decision, it earns its place. I don’t add abstraction layers until a pattern has appeared at least three times. Premature abstraction is worse than duplication in this codebase because the requirements change fast.
