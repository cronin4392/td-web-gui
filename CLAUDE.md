Web UI that communicates back and forth with TouchDesigner.

## Shape of the repo

A pnpm workspace: **one library, two consumers of it.**

| Directory          | What it is                                                                       |
| ------------------ | -------------------------------------------------------------------------------- |
| `packages/td-core` | The library. The only published artifact. Ships its own TD-side Python and docs. |
| `apps/example`     | Reference app, distributed with the package. Doubles as documentation.           |
| `apps/vj-gui`      | The author's real VJ rig. Not published, but maintained and tested.              |

Dependencies point **one way**: both apps depend on `td-core`. Nothing depends on
an app, and the apps never depend on each other. A change that makes `td-core`
aware of an app is going the wrong direction.

Each of the three has its own `CLAUDE.md` with the rules that apply inside it.
Read that one when working there; it is not repeated here.

## The boundary that matters

`td-core` is general-purpose. It knows **instances, params, calls, streams,
readouts** — and nothing else. It must not learn what a Scene, an Effect, a
Layer, a Loader, or a Wordbank is; those are `apps/vj-gui` vocabulary, defined in
`apps/vj-gui/UBIQUITOUS_LANGUAGE.md`.

When an app needs something the library can't do, the question is always
"what is the general capability here?" — add that, and let the app name it.
`loadScene` on the wire is the counterexample already in the tree: an app concept
that reached the protocol and is now a breaking change to undo.

## Working here

- **Build before running an app.** Both apps import `td-core` from its built
  `dist/`, not its source: `pnpm --filter td-core build` first.
- **Changing the wire protocol means changing three places in step** — the
  TypeScript side, `packages/td-core/touchdesigner/*.py`, and
  `packages/td-core/docs/protocol.md`. The Python has no automated coverage, so
  it is the half that silently drifts.
- **Verify with `pnpm test` / `pnpm typecheck`.** Never claim a TD-side Python
  change works without saying it was untested — nothing in CI runs it.
- `pnpm format` (Prettier + Ruff) runs on commit via husky; don't hand-format.

## TouchDesigner rules

`AGENTS.md`, `ENVOY.md`, and `.claude/rules/` are **generated by Embody/Envoy**.
Never hand-edit them; they are overwritten.

Those rules are written for authoring TouchDesigner networks. That is rarely the
task in this repo — this is a web codebase, and the `.toe` files are fixtures for
it. Apply them when actually building or debugging a TD network, and ignore them
when the work is TypeScript.

## Documentation map

Prefer these over re-deriving from source:

| Question                          | File                                           |
| --------------------------------- | ---------------------------------------------- |
| What crosses the wire             | `packages/td-core/docs/protocol.md`            |
| Why the library does an odd thing | `packages/td-core/docs/design-notes.md`        |
| How to set up the TD side         | `packages/td-core/docs/touchdesigner-setup.md` |
| What a vj-gui domain term means   | `apps/vj-gui/UBIQUITOUS_LANGUAGE.md`           |
| What's known-broken / next        | `TODO.md`                                      |

`prds/` is historical and superseded — don't treat it as current design.

`td/` at the repo root holds no project source: it is the venv the Envoy MCP
bridge runs on plus TouchDesigner's logs, both untracked. Don't put files there
and don't delete it. TD-side config lives with the app that owns it —
`apps/vj-gui/td/`, `apps/example/td/`.
